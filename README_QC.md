🧪 **Quality Control (QC) – Tutor Support System (HCMUT)**

---

### 🎯 Mục tiêu
Đảm bảo **chất lượng phần mềm** cho hệ thống **Tutor Support System** tại Trường Đại học Bách Khoa – ĐHQG TP.HCM, bao gồm kiểm thử, phát hiện và báo cáo lỗi, đồng thời xác nhận tính ổn định và khả năng sử dụng của sản phẩm trước khi triển khai chính thức.

Hệ thống hỗ trợ:
- Sinh viên và Tutor trong việc đăng ký, quản lý chương trình học.
- Tạo, hủy, dời lịch hẹn học tập.
- Nhận thông báo, đánh giá buổi học và theo dõi tiến độ.

---

### 🧰 Nhiệm vụ chính của QC
- **Thiết kế và thực hiện Test Case** dựa trên các *Functional Requirements (FRs)* và *Non-Functional Requirements (NFRs)*.  
- **Kiểm thử thủ công (Manual Testing)** các tính năng Frontend và Backend.  
- **Báo cáo lỗi (Bug Report)** trên GitHub Issues hoặc Excel.  
- **Theo dõi kết quả kiểm thử**, xác nhận lỗi đã được fix đúng yêu cầu.  
- **Phối hợp với dev team** để đảm bảo sản phẩm đạt chuẩn về hiệu năng, giao diện và trải nghiệm người dùng.  
- **Viết báo cáo tổng hợp kết quả test** cho mỗi đợt release hoặc sprint.

---

### ⚙️ Công cụ & Kỹ thuật sử dụng
| Thành phần | Công cụ / Công nghệ |
|-------------|--------------------|
| Quản lý test case | Excel |
| Kiểm thử giao diện | Chrome DevTools |
| Kiểm thử API | Postman |
| Theo dõi lỗi | GitHub Issues |
| Theo dõi tiến độ | GitHub Projects |
| Quản lý phiên bản | Git + GitHub |

---

### 📋 Quy trình kiểm thử
1. Phân tích yêu cầu từ tài liệu **SRD** và **Use Case Diagram**.  
2. Thiết lập **test plan** và viết **test case** chi tiết.  
3. Tiến hành kiểm thử từng module (Đăng nhập, Hồ sơ, Đặt lịch, Hủy lịch, Thông báo...).  
4. Ghi nhận kết quả thực tế và so sánh với **Expected Output**.  
5. Báo cáo lỗi, theo dõi việc fix và xác nhận lại.  
6. Tổng hợp kết quả cuối cùng trong **Báo cáo kiểm thử (Test Summary Report)**.
